# Animation Skills Showcase — 86 Styles

A responsive showcase webpage for all 86 animation styles in the library.
Every card shows the skill name on top and one primary still frame beneath
it, generated with that skill's own code. Clicking a card opens a modal with
the skill's description, best use cases, style, 5 extra stills and a ~10 s
demo video with voiceover.

## Theme — LIGHT & cute (user, 2026-11-27 ~00:36 IST; overrides the dark palette)

Exact palette from the Mitsuri avatar (`image-11.png`), no black anywhere:

| Role | Colour |
|---|---|
| Background | `#f9f6fc` cream, `#ebe3d0` soft cream band behind the grid |
| Text / card surfaces | `#405070` dark slate, `#644d5f` deep mauve |
| Text on dark surfaces | `#f9f6fc` cream |
| Accents | `#c07090` braid pink (large display text, bars, borders), `#b0c060` lime green (borders, focus rings, hover) — neither is used as small text: pink on cream is 3.29:1 and lime on slate is 4.06:1, both under the 4.5:1 body-text floor, so small text on dark is cream and small text on light is slate or mauve |
| Borders / dividers | `#b59299` muted mauve |

Font: Baloo 2 (headings) + Quicksand (body), vendored locally in `fonts/`
(`baloo-2.woff2`, `quicksand.woff2`, latin subsets) with system-font
fallbacks — no runtime CDN. Rounded cards (18 px), soft pink-tinted shadows,
pill inputs.

## Layout

- `index.html` + `styles.css` + `app.js` — the page (loads `skills.json`).
  Hero (headline + one sentence + one action + a strip of three real stills
  from done skills, each opening its skill's modal) · The styles (search,
  family filter, count, grid of 86 cards) · footer.
- `skills.json` — generated by `scripts/build-page.py` from
  `assets/<skill>/meta.json`. Each entry also carries `family_key`, the
  source family slug: done skills' `family` is a free-form display label
  (e.g. "Hand-Drawn"), and the filter keys on `family_key` so completed
  skills are never hidden by the family filter.
- `assets/<skill>/` — `still-1.jpg` … `still-6.jpg` + `demo.mp4` + `meta.json`.
- `scripts/watchdog.sh` — monitors `status/<skill>.json` heartbeats, logs
  stalls to `logs/watchdog.log`, enforces the pause gate before the Sunday
  long-form render window.
- `status/` — per-skill progress JSON (heartbeat + state).
- `logs/` — watchdog log + pause flag.

## UI rebuild — 27 Nov 2026 (Hallmark + Impeccable)

The page UI was rebuilt using the two installed design skills
(`~/workspace/custom-skills/hallmark/`, `~/workspace/custom-skills/impeccable/`).
Hallmark (genre playful): hero first, tokens-only colours, no middle-dot
meta strings, no eyebrow, no tracked-caps labels, `overflow-x: clip`,
instant `:focus-visible` rings, reduced-motion fallback, content visible
without scripting (noscript note), one hover signal per card (container
only, image never scales — waived gate 11 on the record, the brief
requires the lift). Impeccable (mode Experience): the artifact leads the
first viewport (real stills in the hero), contrast fixed to WCAG AA
(small text cream-on-slate 7.55:1, slate-on-cream 7.55:1; lime and pink
never as small text), browser surfaces themed (`::selection`,
`caret-color`, scrollbars), video poster from the first still, one
authored motion moment. The data contract is unchanged apart from the
additive `family_key` field (see Layout). Verified locally at 1280×800
and 390×844 (hero fits the fold, no horizontal overflow, search/filter/
modal all work, zero console errors) and by a fresh-context finish review
before deploy.

Finish review (27 Nov 2026, verdict: fix) found 2 P0 + 3 P1 defects, all
fixed in the page code except one render-side item:
- P0 card descriptions: the CSS line-clamp does not hold on this Chromium
  (a flex item's `-webkit-box` display blockifies, so the clamp inserted
  an ellipsis yet still rendered the overflow lines). Fixed by
  deterministic JS truncation (`truncateDesc` in app.js: 140-char budget,
  word boundary, one trailing `...`); the dead clamp rule was removed.
  Verified: all 66 text-only descriptions render at 5 lines or fewer.
- P0 modal video: portrait demos rendered ~978 px tall, pushing controls
  and stills below the fold. Fixed with `max-height: 60vh` on desktop
  (45vh on mobile), video centred; controls + all 5 stills now visible
  on open at 1280×800.
- P1 hero copy: the sentence claimed every card had a real still while
  only 20 of 86 do. It is now dynamic: "N styles have real stills so
  far. The rest are coming." until all 86 are done, then the original
  claim returns.
- P1 card labels: done skills showed display labels while text skills
  showed raw slugs. Names are now Title Case everywhere and families
  show a human label (`displayName`/`displayFamily` in app.js); the one
  done skill whose meta name was a raw slug (stack-split) is covered too.
- P1 blueprint still edge-bleed (KEY PIN / SHEAR LINE cut at the frame
  edge): OPEN, render-side — the still itself needs re-rendering or
  re-cropping with safe margins; the other 19 done stills should be
  audited for the same bleed before the next batch deploys.

## How it was built

86 skills processed in concurrent batches of 10, each skill rendered with
its own engine (stills from the skill's renderer, video from the skill's
frame pipeline, voiceover from the skill's documented voice). Every asset
was verified with ffprobe/file checks before the skill was marked done.

(Updated by the coordinator when the build completes — see the size totals

## Deployment — incremental, batches of 10

The site deploys in batches of 10 skills: as soon as any 10 skills are
fully done (6 stills + ~10 s video each, all verified), `scripts/deploy.sh`
rebuilds `skills.json` and pushes. **Each skill's video goes live TOGETHER
WITH its stills — never a video without its stills, never stills without
the video. A batch deploys only when all 10 skills in it are fully done.**
`skills.json` ALWAYS lists all 86 slots:
finished skills get full cards + modals + media; unfinished skills are
name-only placeholder cards (no broken images, videos or links) until their
batch lands.
